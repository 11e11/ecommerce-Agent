# 面试问题驱动的 Agent Runtime 工程改造

本轮把用户反馈续办、上下文组装、工作记忆和运行轨迹落实为代码。保留原有确定性 Skill Router、DAG、预算受限的 Specialist、Manager/Reviewer 校验链路。

## 从问题到实现

| 高频问题 | 可检查的实现 |
| --- | --- |
| 用户第二次输入怎么办？ | `POST /v1/agent-runs/{runId}/follow-ups` 创建关联父任务的新任务；原任务保持不变 |
| 上下文如何组装？ | 按平台组合目标、当前 Skill、输入 Evidence、审计缺口，以及最多 6000 字符的续办摘要；`context_assembly` 记录组装清单 |
| 工作记忆里存什么？ | 已知证据摘要、未解决问题、执行步骤、剩余预算；规划后、每步取证后和最终状态分别保存快照 |
| 是谁决定调用工具？ | 模型提出调用；计划校验、角色白名单、任务档位、平台固定、调用次数和超时由执行器约束 |
| 为什么继续查询、什么时候停？ | 反思标注步骤覆盖情况；最多一次重规划；预算耗尽或无法补齐时声明不足 |
| 怎样复盘中间过程？ | `GET /v1/agent-runs/{runId}/trace` 聚合计划、记忆、上下文清单及工具调用元数据 |

## 两种运行

一次性任务仍通过 `POST /v1/agent-runs` 创建，再调用 `/execute` 执行。

多轮续办对已完成且审核通过的父任务提交：

```http
POST /v1/agent-runs/{runId}/follow-ups
Idempotency-Key: turn-2
Content-Type: application/json

{"feedback":"保留原文，只列出冲突与证据"}
```

返回一个 `requested` 状态的新任务，调用新任务的 `/execute` 后重新执行 DAG。新一轮重新路由、重新审计继承的输入证据、重新调用分析与审核；尚未实现仅重跑受影响节点。这里的反馈续办不同于 Reviewer 在一次运行内发起的定向返工。

可提供 `objective` 指定新的完整目标，避免反复拼接历史导致目标膨胀。未提供时使用基础目标加当前反馈，仍遵守目标 1000 字符的上限。最近三轮的旧反馈另放在有界上下文中，不把整段聊天历史注入模型。显式提供新目标后，后续轮次以该目标为基础。

`evidence` 可补充新快照，相同 `source_id` 替换继承的输入快照；`evidence_import_ids` 可添加已导入报表。继承的 Metric Observation 通过原始数据库 ID 重新读取，不允许伪造内联指标。前轮工具返回的动态快照不自动变成下一轮输入，按需重新查询。

历史结论只有简短摘要和缺口，不是可引用证据。平台 Specialist 只收到本平台的历史发现。新的 Evidence 仍受现有字段校验、新鲜度检查和引用校验约束。续办上下文与新任务在同一个事务中写入，重用幂等键但修改反馈会被拒绝。

续办绑定父任务图版本，该版本必须仍处于已发布且执行契约兼容的状态；代码变更后，现有租户需按既有流程显式发布新图版本。运行期间不会偷偷改变图或工具权限。

## 可复现的两轮案例

```powershell
ecom\Scripts\python.exe scripts/demo_agent_runtime.py
```

脚本采用临时数据库，不需要凭据，不访问真实店铺。模型和文档工具是明确标记的脚本适配器；DAG 调度、工具执行器、引用校验、工作记忆、反思重规划、续办和 Reviewer 都走实际项目代码。这不是外部真实模型效果评测，也未验证 MCP 子进程传输。

第一轮：查询模拟规则，发现“7天改为3天”；由于现有流程未知，反思为部分充分；重新规划后查到“现有流程允许5天”，形成冲突发现并交给 Manager/Reviewer。第二轮用户要求“保留原文，只列冲突与证据”，新任务收到限定历史和反馈，重新取证并更新报告。脚本打印工具调用、反思、重规划、上下文清单及记忆快照数量。

## 验证与面试表述

```powershell
ecom\Scripts\python.exe -m pytest tests/test_continuations.py tests/test_specialist_harness.py tests/test_harness_integration.py tests/test_agent_graphs.py tests/test_runtime.py -q
```

重点验证旧任务不变、同 ID Evidence 替换、续办重新审计、平台历史隔离、幂等冲突、跨租户拒绝、HTTP 入口和轨迹可读性。

可以据实说：外层 DAG 固定协作顺序，内层 Specialist 在预算内规划、调用只读工具和反思；用户再次输入时创建关联新任务，使用有界历史重新分析，保留两轮的完整审计记录。这里的“有界”覆盖历史上下文和工作记忆，输入 Evidence 仍遵守原有 20 份/800KB 限制，不代表整个模型输入已有精确 Token 预算。

本轮不改变路由或 RAG 指标。现有 227 条路由集的可复现报告与旧简历数字必须分开；Skill 效果评测、规则与模型路由对照、大规模 Skill 检索和真实模型评测仍需独立推进，不能把这次模拟演示当作效果提升数据。
